# 004 — 三源 engagement 接入与 Reddit 桥预检自愈

> Triage: `ready-for-agent`

## Problem Statement

两个遗留问题：

1. **engagement 维度名不副实**。评分五维中的 engagement（热度）目前只有 GitHub 有真实信号（star 数 log10 压缩），X 和 Reddit 一律取中性 50。而这两个源恰恰是互动信号最丰富的平台——X 采集器的上游 CLI 本来就返回 likes/views/retweets，却在构造条目时被丢弃；Reddit 在 opencli 桥接入后已携带真实评论数，却没有进评分。结果：一条 15 万赞的 Karpathy 爆推和一条 5 赞的随手转发，综合分里热度贡献完全相同，准入与排序失去一个本可用的判据。

2. **Reddit 桥在无人值守时段不可用且浪费等待**。桥依赖登录态 Chrome 会话（扩展在线）。每日 08:00 调度生成时用户大概率还没开浏览器——每条子版块命令要磨满 45s 超时才报"扩展未连接"，5 个 sub 白等约 4 分钟才降级到匿名 Atom feed，且降级丢失全部互动元数据。桥形同虚设，还拖慢整期生成。

## Solution

1. **engagement 三源接入**：热度维度按来源分派——GitHub 用 star 数（既有，锚 20k）、X 用点赞数（log10 压缩，锚 10 万）、Reddit 用评论数（log10 压缩，锚 500）。X 采集器补存 likes/views/retweets 互动快照。无信号源（web、Atom 降级日的 Reddit）维持中性 50。

2. **Reddit 桥预检自愈**：桥执行前先做连通性预检（约 1s）；不通则在 Windows 上自动拉起 Chrome 并限时复探（预算 15s）；仍不通立即降级 Atom，不再逐 sub 磨超时。08:00 无人值守时桥能自我救活，救不活也只多花约 16s。

## User Stories

1. 作为读者，我想让"热度"维度反映条目在真实社区里的反响，这样我扫一眼评分就知道这条是刷屏级还是小圈子内部讨论。
2. 作为读者，我想让 X 来源的爆推（高赞）在榜单和"必读"判定中获得应有的热度权重，这样编辑推荐的 Top3 不会漏掉当天真正出圈的内容。
3. 作为读者，我想让 Reddit 来源的热帖（高评论数）区别于无人问津的帖子，这样 Reddit 条目之间的相对排序有依据。
4. 作为读者，我不希望热度分把"大 V 随手发"和"大 V 精品爆款"混为一谈，这样点赞数对数的压缩让爆款和日常拉开档位而顶部不失真。
5. 作为读者，我希望 web 来源（RSS 博客）保持中性热度，这样没有平台互动信号的内容不会因为热度维度被系统性压低综合分。
6. 作为读者，我希望 Atom 降级日生成的 Reddit 条目仍能正常进榜（热度中性），这样浏览器桥偶然不可用不影响我照常读到日报。
7. 作为系统运维者，我希望 08:00 调度生成时若 Chrome 未开，系统能自动拉起浏览器让桥上线，这样 Reddit 通道在无人值守时段依然可用。
8. 作为系统运维者，我希望桥预检失败且自愈失败时立即降级到 Atom feed，这样不会为死桥浪费 4 分钟超时等待。
9. 作为系统运维者，我希望在服务器/容器（无桌面）环境部署时，拉起浏览器的尝试无害失败并直接降级，这样同一套代码桌面和服务器都能跑。
10. 作为系统运维者，我希望本期走了哪条通道（opencli / atom）以及预检结果（通过/已拉起/降级）在日志里可查，这样排查"今天 Reddit 数据为什么没热度"有迹可循。
11. 作为开发者，我想让热度计算保持单入口纯函数（输入来源键 + 互动信号，输出 0-100），这样三源策略可以参数化测试，新增源只改一处。
12. 作为开发者，我想让 X 采集器把互动快照（likes/views/retweets）落进条目 extra，这样未来重标定锚点或更换信号时有历史数据，不必改采集层再等几期。
13. 作为开发者，我想让预检逻辑内聚在 Reddit 桥模块内部，这样调度器和采集编排器不感知某个渠道的内部依赖细节。
14. 作为数据校准者（未来的我），我想让三个锚点以具名常量集中在评分模块顶部并附换算注释，这样调整标度只动常量不动公式。
15. 作为领域文档维护者，我希望 CONTEXT.md 的「评分」词条与三源压缩现实同步，这样架构讨论引用的领域语言不会过期。

## Implementation Decisions

### 热度计算（scorer）

- `compute_engagement` 保持现有签名（来源键 + extra 字典 → 0-100 整数），内部按来源分派：
  - GitHub：`100 × log10(1+stars) / log10(1+20000)`（既有行为，锚 20k★=100）
  - X：`100 × log10(1+likes) / log10(1+100000)`（新，锚 10 万赞=100）
  - Reddit：`100 × log10(1+num_comments) / log10(1+500)`（新，锚 500 评=100）
  - 其余（web、无信号的 Reddit）：50 中性（既有行为）
- 三个锚点为具名常量，附换算表注释（X：100赞≈40/1k≈60/1万≈80；Reddit：10评≈42/50评≈62/100评≈74）。锚点依据 2026-08-18 四个 KOL × 15 推的实采分布校准。
- 锚点语义差异是刻意的：star/赞/评论是三个量纲，各配各的锚，不共用。
- views 不参与评分（曝光与互动强相关，加了没有增量信息），但落库留存。

### X 采集层

- 构造条目时把上游 CLI 返回的 `likes` / `views` / `retweets` 三个互动快照写入 extra（与既有 author/tweet_id 并列）。推文互动数是易变快照，错过采集窗口不可再生，因此按"可能有用就存"落库。
- 缺失/非数值的 metrics 容错为不写入（边界容错，不猜默认值）。

### Reddit 桥预检自愈

- 预检位于桥模块的采集入口最前部，流程：
  1. 连通性探测（opencli 诊断命令子进程，约 1s）——通过则直接进入逐 sub 采集；
  2. 不通且运行于 Windows 桌面 → 启动默认 Chrome → 约 8s 后复探 → 仍不通再等约 7s 末次复探（总预算约 15s）；
  3. 三次探测全部失败 → 本次采集立即返回空，由既有分派逻辑无缝降级 Atom。
- 拉启动作仅在 Windows 尝试且全程 try/except 包裹——服务器/容器上启动失败是无害的，直接落入降级。
- 预检三态记入日志：通过 / 拉起后通过 / 降级，与既有 `channel=` 日志字段配套。
- 预检不在 kill switch（AIDAILY_REDDIT_DISABLE_OPENCLI）开启时执行——开关直接跳过整个桥。

### 领域文档

- CONTEXT.md「评分」词条更新：engagement 从"GitHub star log10 压缩，无信号源取中性 50"改为三源压缩表述（GitHub star / X 赞 / Reddit 评论，各配独立锚点，无信号源中性 50）。

## Testing Decisions

- **好测试只测外部行为**：不 mock 内部私有函数，全部通过既有公开接缝注入伪造依赖（子进程 stub / respx）后断言产出。
- **零新接缝**，三个测试面全部复用既有模式：
  1. `compute_engagement` 纯函数——现有 scorer 单测惯例，扩展为三源参数化用例（各锚点边界值、量纲隔离、信号缺失回中性、坏类型容错）；
  2. X 采集器——复用 twitter-cli 子进程 stub 模式，断言 extra 含三个互动键及缺失容错；
  3. Reddit 桥——复用 opencli 子进程 stub 模式，把预检探测/拉起/复探也纳入子进程 stub 序列，覆盖预检三岔（直通 / 拉起后通 / 全败返空）。
- 预检的 sleep 等待必须可注入或可跳过，禁止测试真实等待 15s。
- 真机验收两轮：Chrome 关闭状态跑桥采集（验证自动拉起与 channel 日志）；kill switch 开启跑（验证直接 Atom）。
- Prior art：`tests/unit/test_individual_collectors.py` 的子进程 stub 与 respx 模式、`tests/unit/test_reddit_opencli.py` 的桥 stub 模式。

## Out of Scope

- Reddit 赞数（score）接入——opencli 的 subreddit 命令当前恒返回 null，待上游适配器修复后再议复合信号。
- X 的 views / retweets 参与评分——本期待重标定时使用，不进公式。
- web 源的热度信号——RSS 无平台互动数据，维持中性。
- LLM 评分增强路径的调整——热度维度本就由规则计算覆盖 LLM 输出，无 LLM 侧改动。
- Chrome 拉起后的窗口管理（最小化、关闭策略）——接受 08:00 桌面弹出 Chrome 窗口的副作用。
- 综合分权重调整——五维权重不动，只有 engagement 维度的取值来源变准。

## Further Notes

- 锚点常量与换算表注释是刻意的"决策即文档"：未来调标度的人看注释就能推演新旧分数差异，不用读公式反推。
- X 锚点 10 万的校准依据（2026-08-18 实采）：karpathy 中位赞 1.9 万→78 分、爆推 15 万→封顶；ylecun 中位 3k→70；simonw 日常 115→41、爆款 1.9 万→78；swyx 日常 46→33。跨 KOL 与同 KOL 内部均有区分度。
- Reddit 锚点 500 的量纲依据：AI 类 sub 是小圈子，r/MachineLearning 周榜热帖通常 30-150 评；复用 GitHub 的 20k 锚会把全部 Reddit 内容压到 40 分以下。
